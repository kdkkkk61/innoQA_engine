### 1. 오버플로 테스트 — EDIT 모달 지원 (`validators/overflow.py`)

**문제**  
예외처리 목록(파일경로 / 프로세스경로 / 전자서명) 오버플로 테스트가 타임아웃 발생.  
ADD 모달은 예외처리 탭에 접근할 수 없어 기다리기만 하다 실패.

**해결**  
YAML `overflow_tests.cases[].modal: "edit"` 옵션 추가.  
해당 케이스는 ADD 모달 대신 p2 수정 모달(EDIT 모달)을 경유하도록 분기.

```yaml
# config/scan_hints/ransom_detect_policy.yaml
overflow_tests:
  edit_register_btn: "button[modify-btn]"
  edit_cancel_btn:   "button[data-dismiss='modal']"
  cases:
    - label: "파일경로 예외처리 오버플로"
      modal: "edit"
      fill_required:
        - { type: "toggle_on", selector: "input#isExceptDetect" }
```

**추가 버그 수정**  
`fill_required` 루프에서 `toggle_on` / `tag_add` 타입 처리 후에도 `loc.fill("")`을 호출해 체크박스에 fill 시도하던 버그 수정 → `continue`로 즉시 다음 항목으로 이동.

**스크린샷 자동 캡처**  
오버플로 결과가 `error` 또는 `known_bug`일 때 스크린샷 자동 저장 (`reports/screenshots/OVERFLOW_*.png`).  
결과 `extra["screenshot"]` 필드에 경로 저장 → HTML 리포트 연동 가능.

```python
# core/qa_runner.py
def _tag_scenario(report, scenario):
    if report is None: return
    for r in report.results:
        r.extra["scenario"] = scenario
```

### 3. HTML 리포트 시나리오 그룹핑 수정 (`core/html_reporter.py`, `templates/app/report.html`)

**수정**

```python
"is_list": any(r.pattern in {
    "list_crud", "list_modify", "list_modify_save",
    "list_modify_verify", "list_modify_bug", "list_button",
} for r in rep.results),
```

**문제 2 — `groupByScenario()` 잘못된 로직**  
order 범위 / phase 번호로 그룹을 추정하던 방식 → 탭 위치 기준 분류.

**수정**  
`r.scenario` 필드 직접 사용하도록 완전 재작성:
```javascript
function groupByScenario(results, isList) {
    const sorted = [...results].sort((a, b) => {
        const sa = a.scenario || a.phase || 0;
        const sb = b.scenario || b.phase || 0;
        return sa !== sb ? sa - sb : (a.order||9999)-(b.order||9999);
    });
    const map = new Map();
    for (const r of sorted) {
        const num = r.scenario || r.phase || 0;
        const label = SCENARIO_LABELS[num] || `시나리오 ${num}`;
        if (!map.has(label)) map.set(label, []);
        map.get(label).push(r);
    }
    return map;
}
```

**JSON 출력에 `"scenario"` 필드 추가** (`html_reporter.py`):
```python
"scenario": (r.extra or {}).get("scenario"),
```

### 4. QA앱 진행뷰 시나리오 1~5 사전 정의 (`app.py`)

**문제**  
시나리오 5가 시나리오 4 완료 후에야 진행뷰에 나타나는 통일성 이슈.

**해결**  
`_MODAL_SCENARIOS` / `_LIST_SCENARIOS` 에 시나리오 1~5 전부 사전 정의.  
`_SKIP_RE` 정규식으로 `⏭ 시나리오 N:` 출력 감지 → 즉시 `stopped` 상태로 표시.

```python
_MODAL_SCENARIOS = [
    {"num": 1, "label": "시나리오 1: UI 구조  (탭 · 테이블 · 검색)",          "status": "pending"},
    {"num": 2, "label": "시나리오 2: 입력 구조  (모달 필드 · 초기값 · 필수입력)", "status": "pending"},
    {"num": 3, "label": "시나리오 3: 동작 검증  (CRUD · 오버플로 · 중복 처리)", "status": "pending"},
    {"num": 4, "label": "시나리오 4: 수정 시나리오  (저장값 로드 · 재확인)",    "status": "pending"},
    {"num": 5, "label": "시나리오 5: 케이스 검증  (제품 설정 ON/OFF 프로파일)", "status": "pending"},
]

_SKIP_RE = re.compile(r'[⏭]\s*시나리오\s+(\d+)')
```

### 시나리오 번호 표준 (CLAUDE.md 기준)

| 번호 | 이름 | modal_form | list_page |
