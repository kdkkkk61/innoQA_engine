# QA Tool — 앱 설계 문서

> 작성 목적: 개발자 + QA 담당자가 같이 방향을 잡고 구현 전에 합의하는 문서.
> 구현 시작 전 이 문서를 기준으로 진행한다.

---

## 1. 제품 비전

**"cmd 없이, 버튼 하나로 테스트 → 리포트까지"**

현재: pytest 명령어 입력 → 터미널 출력 확인 → HTML 리포트 수동 확인
목표: 앱 실행 → 제품/테스트 선택 → 실행 → 리포트 편집 → 최종 제출

### 핵심 포인트
- **Playwright 브라우저 창이 직접 보이는 것이 메인 가치**
  터미널 출력 스트리밍보다 실제 브라우저가 테스트하는 화면을 보여주는 게 중요
- 앱 창은 제어판 역할 (시작/중단/상태 표시)
- QA 담당자가 직접 발견한 버그를 리포트에 추가할 수 있어야 함

## 2. 화면 흐름

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  ① 제품 선택 │────▶│ ② 테스트 선택│────▶│ ③ 실행 설정  │
└─────────────┘     └─────────────┘     └──────┬──────┘
                                                │ [테스트 시작]
                                                ▼
                                        ┌─────────────┐
                                        │  ④ 진행 화면  │  ← Playwright 브라우저 별도 창
                                        │  (앱은 상태   │
                                        │   표시만)    │
                                        └──────┬──────┘
                                                │ 완료
                                                ▼
                                        ┌─────────────┐
                                        │ ⑤ 1차 리포트  │  ← 수동 결함 추가/편집
                                        └──────┬──────┘
                                                │ [최종 완료]
                                                ▼
                                        ┌─────────────┐
                                        │ ⑥ 최종 리포트 │  ← HTML 다운로드
                                        └─────────────┘
```

## 3. 화면별 상세 설계

### ① 제품 선택
- 등록된 제품 목록을 카드 형태로 표시
- 현재: 랜섬크런처만 활성화, 나머지 비활성(회색) 표시
- 제품 추가 시 `pages/registry.py`의 `MODULE_GROUPS`에 추가하면 자동 반영
- 선택 후 [다음] 버튼

```
┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│  랜섬크런처   │  │   제품 B     │  │   제품 C     │
│   ✅ 활성    │  │  (준비 중)   │  │  (준비 중)   │
└──────────────┘  └──────────────┘  └──────────────┘
```

### ② 테스트 선택
- 선택한 제품에서 사용 가능한 테스트 종류 표시
- 현재: UI/UX 테스트만 활성화
- 추후: 정책 적용 테스트 (test_profiles 기반) 추가 예정

```
┌───────────────────────┐  ┌───────────────────────┐
│  UI/UX 테스트          │  │  정책 적용 테스트       │
│  탭/버튼/모달/CRUD 검증 │  │  (추후 추가)           │
│  ✅ 활성               │  │  🔒 준비 중            │
└───────────────────────┘  └───────────────────────┘

  테스트 대상 페이지 (체크박스):
  ☑ 탐지정책   ☑ RDP 정책   ☑ 공통 프로세스
```

### ③ 실행 설정
- ID / PW 입력 필드
- [테스트 시작] 버튼

```
  매니저 계정 입력
  ID  : [________________]
  PW  : [················]
       [ 테스트 시작 ]
```

### ④ 진행 화면 (앱 창 역할)

**핵심: Playwright 브라우저 창이 메인. 앱 창은 상태만 표시.**

```
  현재 진행 중: 탐지정책 (2/3)

  ┌─ 완료 ──────────────────────────────┐
  │  ✅ 탐지정책   pass=84 bug=3        │
  └─────────────────────────────────────┘
  ┌─ 진행 중 ───────────────────────────┐
  │  🔄 RDP 정책   스캔 중...           │
  └─────────────────────────────────────┘
  ┌─ 대기 ──────────────────────────────┐
  │  ⏳ 공통 프로세스                    │
  └─────────────────────────────────────┘

  [ 중단 ]
```

- Playwright 브라우저는 `headless: false` 로 별도 창에서 동작 (기존 설정 유지)
- 앱 창은 페이지별 진행 상태만 표시 (완료/진행중/대기)
- 에러로 종료된 경우 에러 로그 표시
- [중단] 버튼: 즉시 종료 (부분 리포트 없음)

### ⑤ 1차 리포트 — 편집 모드

**편집 모드 기능 (확정 전):**

```
┌──┬─────────────────────┬────────┬──────────┬──────────┬──────────┬────┐
│+ │ 항목명              │ 상태   │ 기댓값   │ 실제결과 │ 의견/메모│ 📷 │
├──┼─────────────────────┼────────┼──────────┼──────────┼──────────┼────┤
│+ │ 탐지등급 초기값 없음 │[⚠️BUG]│ 선택됨  │ 없음     │ [편집]   │[🖼]│
├──┼─────────────────────┼────────┼──────────┼──────────┼──────────┼────┤
│+ │ 인증암호 ON/OFF 버그 │[⚠️BUG]│ 비활성화 │ 활성유지 │ [편집]   │[🖼]│
└──┴─────────────────────┴────────┴──────────┴──────────┴──────────┴────┘
```

| 컨트롤 | 동작 |
|--------|------|
| 행 앞 `+` | 해당 행 바로 아래에 새 빈 행 삽입 |
| `[⚠️BUG]` 클릭 | ✅PASS → ⚠️BUG → ❌FAIL 순환 토글 |
| 항목명/기댓값/실제결과/의견 셀 | 클릭하면 직접 편집 가능 |
| `[🖼]` | 이미지 파일 선택 → 미리보기 표시 |
| 행 우클릭 또는 삭제 버튼 | 해당 행 삭제 |

**확정 버튼 누르면:**
- 편집 컨트롤(+버튼, 토글, 삭제 등) 모두 사라짐
- 입력한 내용과 스크린샷이 그대로 고정된 뷰로 전환
- 최종 HTML 파일 생성 + 저장 경로 선택

### ⑥ 최종 리포트
- 편집 확정된 내용(자동 결함 + 수동 추가 + 의견 + 스크린샷) 포함
- 편집 UI 없는 순수 보고서 형태
- HTML 파일로 저장 (수신자에게 그대로 전달 가능)

## 4. 기술 스택

| 항목 | 선택 | 이유 |
|------|------|------|
| UI 프레임워크 | **PyWebView** | 네이티브 앱 창, EXE 패키징 가능 |
| 백엔드 | **Flask** | 기존 Python 코드 그대로 재사용 |
| 테스트 실행 | subprocess (pytest) | 기존 구조 유지, Playwright 창 별도 표시 |
| 패키징 | PyInstaller | 단일 EXE 배포 가능 |

```
app.py (Flask + PyWebView)
├── templates/         ← 각 화면 HTML
│   ├── index.html     ← ① 제품 선택
│   ├── test_type.html ← ② 테스트 선택
│   ├── run.html       ← ③ 실행 설정
│   ├── progress.html  ← ④ 진행 화면
│   └── report.html    ← ⑤ 1차 리포트
├── core/              ← 기존 코드 그대로
├── pages/             ← 기존 코드 그대로
└── config/
    └── manual_bugs.yaml  ← 수동 결함 저장
```

---

## 5. 데이터 흐름

```
사용자 선택
  → app.py 가 pytest subprocess 실행
  → pytest가 Playwright 브라우저 창 띄워서 테스트
  → 완료 후 PageScanReport 반환
  → html_reporter.py 가 1차 HTML 생성
  → 사용자가 manual_bugs.yaml 편집 (앱 내 폼)
  → html_reporter.py 가 최종 HTML 생성 (수동 결함 포함)
```

## 6. 확정된 설계 결정

| # | 항목 | 결정 |
|---|------|------|
| 1 | 진행 화면 | Playwright 브라우저 창이 메인. 앱 창은 페이지별 상태만 표시 |
| 2 | 중단 | 즉시 종료. 에러 종료 시 로그 표시 |
| 3 | 수동 결함 | 매 실행마다 새로 작성 (이전 내용 재사용 없음) |
| 4 | 최종 리포트 저장 | 저장 경로 사용자 선택 (파일 다이얼로그) |
| 5 | EXE 패키징 | 우선 `python app.py` 실행으로 시작, 추후 PyInstaller |
| 6 | 편집 확정 후 | 편집 컨트롤 완전히 제거된 순수 보고서로 전환 |

## 7. 구현 순서 (단계별)

- [ ] Phase 1: 뼈대 — `app.py` + PyWebView + Flask 실행 확인
- [ ] Phase 2: 화면 흐름 — ①②③ 화면 이동 (제품선택/테스트선택/실행설정)
- [ ] Phase 3: 테스트 실행 — subprocess pytest 연동 + ④ 진행 화면 (상태 표시)
- [ ] Phase 4: 1차 리포트 — ⑤ 인라인 편집 테이블 (행추가/상태토글/의견/스크린샷)
- [ ] Phase 5: 최종 리포트 — 확정 후 편집 UI 제거 + HTML 저장
- [ ] Phase 6: 패키징 — PyInstaller EXE (추후)
